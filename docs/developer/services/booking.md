# Booking

Главный сервис: бронирование мест, игровые сессии, отчёты, уведомления. Самый большой по объёму и числу тестов.

## Что делает

- **Бронь**: выбор времени и мест, проверка доступности, расчёт цены и сохранение в одной транзакции ([ADR 0004](/adr/0004-booking-reservation-in-one-transaction)). Повторная отправка той же брони не создаёт дубль (заголовок `Idempotency-Key`);
- **Игровые сессии**: заселение по брони, гостевая сессия без аккаунта, продление, пересадка, завершение, отметка об оплате (оплата принимается только в клубе);
- **Автоматика по расписанию**: неявка через 15 минут после начала, напоминание перед визитом, предупреждение об окончании;
- **Уведомления**: письмо игроку и запись в таблице уведомлений (её отдаёт `GET /notifications`, а кабинет показывает как раздел «Уведомления»), повтор при ошибке;
- **Отчёты** для администратора, ежедневные сводки, CSV-выгрузка;
- **События сайта** (`POST /api/booking/events`): просмотры страниц и начало бронирования для воронки в отчётах; посетитель обезличен суточным хешем.

## API (`/api/booking/*`)

Для игрока: `availability`, `bookings` (список, создание, просмотр, отмена), `sessions`, `notifications`, `events`.

Для администратора (`/admin/*`):

| Группа     | Пути                                                                           |
| ---------- | ------------------------------------------------------------------------------ |
| брони      | `bookings` (список, создать), `bookings/{id}/check-in`, `bookings/{id}/cancel` |
| сессии     | `sessions` (список, гость), `sessions/{id}/end`, `extend`, `move`, `pay`       |
| посетители | `users/{id}/history`                                                           |
| отчёты     | `reports`, `daily-reports`, `report-exports` (список, заказ, скачивание)       |
| состояние  | `processing`, `notifications` (+ `retry`), `audit`                             |

## Правила (настройки в `config/shift.php`)

| Правило                   | По умолчанию                       | Переменная                |
| ------------------------- | ---------------------------------- | ------------------------- |
| шаг начала брони          | 30 минут                           | `BOOKING_STEP_MINUTES`    |
| максимальная длительность | 12 часов                           | `BOOKING_MAX_MINUTES`     |
| горизонт бронирования     | 30 дней                            | `BOOKING_HORIZON_DAYS`    |
| заселение до начала       | 15 минут (`prod`), 30 дней (`dev`) | `CHECKIN_EARLY_MINUTES`   |
| неявка после начала       | 15 минут                           | `NO_SHOW_GRACE_MINUTES`   |
| срок хранения CSV         | 24 часа                            | `REPORT_EXPORT_TTL_HOURS` |

## Данные

`bookings`, `booking_items`, `allocations` (занятость места по времени), `gaming_sessions`, `idempotency_keys`, `notifications`, `report_exports`, `daily_club_reports`, `site_events`, `audit_entries`, копия каталога `workstations`, `outbox`, `inbox`.

## Процессы (каждый — отдельный контейнер)

| Контейнер                     | Команда                            | Задача                        |
| ----------------------------- | ---------------------------------- | ----------------------------- |
| `booking`                     | веб-сервер                         | HTTP API                      |
| `booking-worker`              | `events:consume`                   | принимает события из RabbitMQ |
| `booking-notification-worker` | `queue:work --queue=notifications` | отправляет письма             |
| `booking-report-worker`       | `queue:work --queue=reports`       | формирует CSV                 |
| `booking-scheduler`           | `schedule:work`                    | расписание ниже               |

Расписание: `events:publish` каждые 10 с (отправка outbox), `club:reconcile` и `club:sync` каждую минуту (неявки, напоминания, сверка каталога), `reports:daily` каждые 30 минут (сводка за закончившиеся дни), `reports:prune` раз в час (удаление просроченных CSV).

## CSV-выгрузка отчёта

**Зачем.** Администратор выгружает показатели клуба за период, чтобы открыть их в Excel или передать бухгалтеру.

**Как работает.**

1. В админке «Отчёты» выберите период (и при желании зону) и нажмите выгрузку CSV. Запрос `POST /admin/report-exports` сразу отвечает `202` и создаёт запись `report_exports` со статусом `pending`.
2. Задача `GenerateReportExport` уходит в очередь `reports`. Её берёт `booking-report-worker`: ставит `processing`, считает отчёт теми же формулами, что и страница отчётов, пишет файл `storage/app/private/reports/<uuid>.csv` и ставит `ready`. При сбое статус `failed` и сообщение «Создайте выгрузку ещё раз».
3. Готовый файл появляется в списке; скачать его (`GET …/download`) может только заказавший администратор. Через 24 часа файл удаляет `reports:prune`, статус становится `expired`.

**Что внутри.** Файл рассчитан на русский Excel: разделитель — точка с запятой, в начале стоит BOM (UTF-8), суммы в рублях с десятичной запятой, даты вида `13.10.2026`. Три раздела, разделённые пустой строкой:

1. **Сводка за период**: шапка (период, охват — весь клуб или зона, часовой пояс, время формирования) и таблица «Показатель; Значение; Единица; Пояснение»: брони (подтверждены, отменены, неявки), сессии, начислено, оплачено, не оплачено, занятость и загрузка, показатели сайта.
2. **По дням**: строка на каждый день периода (брони, неявки, сессии, начислено и оплачено в ₽, часы, загрузка, просмотры и начатые бронирования).
3. **По зонам** (только если выбран весь клуб): сводка по каждой зоне за период. Названий зон Booking не хранит (они в сервисе Club), поэтому зоны подписаны как «Зона №1».

Сборкой занимается `app/Services/ReportCsvBuilder.php`, задача `GenerateReportExport` только сохраняет результат. «Не оплачено» — оценка (начислено минус оплачено за период). После изменения кода перезапустите воркер (`docker compose restart booking-report-worker`): он долгоживущий и держит старый код в памяти.

**Как проверить.**

- Вручную: «Отчёты» → «Выгрузить CSV» → дождаться статуса «Готово» (обычно несколько секунд) → «Скачать». Если статус не меняется, проверьте, что запущен `booking-report-worker`: `docker compose ps booking-report-worker`.
- Автоматически: `pnpm exec playwright test admin-reports` проходит весь путь «заказ → готово → скачивание».
- Через API: `POST /api/booking/admin/report-exports` (с cookie администратора и CSRF-токеном), затем `GET /api/booking/admin/report-exports` до статуса `ready` и `GET /api/booking/admin/report-exports/{id}/download`.
- Состояние очереди и ошибок видно в разделе «Обработка» админки.
