# Identity

Сервис аккаунтов. Единственный, кто хранит пароли и выдаёт токены; остальные сервисы только проверяют токен.

## Что делает

- регистрация и вход по email и паролю (пароль 12–72 символа), хеш хранится только в базе Identity;
- выдача короткоживущего access-токена (JWT, подпись RS256, живёт 15 минут) и долгоживущего refresh-токена, оба в HttpOnly-cookie;
- ротация refresh-токена, список устройств (сеансов входа), отзыв одного устройства или всех сразу;
- восстановление пароля: письмо со ссылкой на 60 минут, повторное письмо не чаще раза в минуту;
- роли `player` и `admin`; список посетителей для администратора;
- внутренняя проверка токена для других сервисов (`introspect`).

## API (`/api/auth/*`)

| Метод и путь                                            | Назначение                                |
| ------------------------------------------------------- | ----------------------------------------- |
| `GET /csrf`                                             | выдать CSRF-токен (cookie `XSRF-TOKEN`)   |
| `POST /register`, `POST /login`                         | регистрация и вход                        |
| `POST /refresh`                                         | обновить access-токен по refresh          |
| `POST /logout`, `POST /logout-all`                      | выйти на этом устройстве / на всех        |
| `GET /me`, `PATCH /me`                                  | текущий пользователь, смена имени         |
| `GET /sessions`, `DELETE /sessions/{id}`                | устройства и отзыв                        |
| `POST /forgot-password`, `POST /reset-password`         | восстановление пароля                     |
| `GET /admin/users`                                      | поиск посетителей (только `admin`)        |
| `POST /internal/introspect`, `GET /internal/users/{id}` | внутренние вызовы, нужен `INTERNAL_TOKEN` |

Вход и регистрация ограничены по частоте с одного IP (`AUTH_RATE_LIMIT`: 10 в минуту в `prod`, 1000 в `dev`).

## Данные

Таблицы: `users`, `auth_sessions`, `refresh_tokens`, `password_reset_tokens`, `sessions`, `outbox`, `inbox`, а также служебные `cache` и `jobs`.

## Безопасность

- Пароли хранятся хешами, в логах только номера пользователей.
- Refresh-токен одноразовый. Повторное использование спустя больше 5 секунд считается кражей: сеанс отзывается. Повтор в пределах 5 секунд — обычная гонка двух вкладок, сервер просит повторить запрос с новым cookie.
- Заблокированный пользователь (`blocked_at`) войти не может.
- При неверном входе ответ один и тот же для «нет такого email» и «неверный пароль» (`401 Неверный email или пароль.`), а проверка bcrypt выполняется и для несуществующего адреса, чтобы по времени ответа нельзя было угадать адрес.
- Письма уходят через SMTP; локально их перехватывает Mailpit (контейнер `mailpit`, наружу письма не уходят).

## События

Таблица `outbox` и команда `events:publish` готовы, но сейчас Identity события не публикует: другим сервисам хватает внутреннего запроса `introspect`.

## Файлы

`app/Http/Controllers/AuthController.php` (все эндпоинты), `app/Services/TokenService.php` (JWT и ротация), `config/shift.php` (лимиты и адреса).
