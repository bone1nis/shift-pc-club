# Club

Сервис справочника клуба: что есть в зале, сколько это стоит и как клуб выглядит для гостей. Бронирования он не знает.

## Что делает

- **Зоны** (Арена, VIP): название, описание, добавление и правка администратором;
- **Компьютеры**: координаты на схеме, характеристики (процессор, видеокарта, память, монитор) и статус `available` / `maintenance`;
- **Тарифы**: цена часа для зоны, каждое изменение повышает версию тарифа;
- **Профиль клуба**: название, слоган, адрес, ориентир, телефон, email, координаты, часы работы. Этот текст показывается на сайте в «Контактах» и в подвале;
- **Журнал действий** администратора (`audit_entries`).

## API (`/api/club/*`)

| Метод и путь                                   | Доступ  | Назначение                                              |
| ---------------------------------------------- | ------- | ------------------------------------------------------- |
| `GET /catalog`                                 | все     | зоны, компьютеры и тарифы                               |
| `GET /profile`                                 | все     | профиль клуба                                           |
| `POST /admin/zones`, `PATCH /admin/zones/{id}` | админ   | создать и изменить зону                                 |
| `PATCH /admin/workstations/{id}`               | админ   | изменить компьютер, в том числе вывести на обслуживание |
| `PATCH /admin/tariffs/{id}`                    | админ   | изменить цену                                           |
| `PATCH /admin/profile`                         | админ   | изменить профиль клуба                                  |
| `GET /admin/audit`                             | админ   | журнал действий                                         |
| `GET /internal/catalog`                        | сервисы | каталог для Booking                                     |

## Данные

Таблицы: `zones`, `workstations`, `tariffs`, `club_profile` (одна запись), `audit_entries`, `outbox`, `inbox`.

## События

При любом изменении каталога Club в той же транзакции пишет в `outbox` событие `club.catalog.updated`; Booking подхватывает его и обновляет свою копию каталога (`CatalogProjection`). Если событие потерялось, Booking раз в минуту сам сверяется командой `club:sync`.

## Вывод компьютера на обслуживание

Club не знает о бронях, поэтому перед переводом места в `maintenance` вызывает внутренний метод Booking (`/api/booking/internal/workstations/{id}/maintenance`). Если на это место есть будущие брони, Booking их отменяет с уведомлением игрокам; только после ответа Club меняет статус. Подробности — в [ADR 0006](/adr/0006-maintenance-coordination).
