Здесь описано, какие библиотеки используют сайт и админка, зачем они нужны и как работают. Остальное (UI-кит, календарь, поповеры) написано самостоятельно, поэтому лишних зависимостей мало.

## TanStack Query (vue-query)

### Проблема, которую он решает

Раньше кабинет игрока сам вызывал `api()`, хранил ответ в `ref`, ставил `setInterval` на 30 секунд и руками следил за флагами `loading` и `error`. Такой код надо писать заново для каждой страницы, и в нём легко ошибиться: забыть остановить таймер, показать устаревшие данные или запустить два одинаковых запроса.

### Как это работает

Библиотека держит **кэш запросов**. Каждый запрос описывается ключом (`queryKey`) и функцией, которая получает данные (`queryFn`):

```ts
const query = useQuery({
  queryKey: ['account'], // ключ в кэше
  queryFn: loadAccount, // как получить данные
  enabled: signedIn, // не запрашивать, пока игрок не вошёл
  refetchInterval: 30_000, // обновлять раз в 30 секунд
})
// query.data, query.isPending, query.error, query.refetch()
```

Что происходит внутри:

1. **Первый вызов.** Данных в кэше нет, запрос уходит на сервер, пока `isPending = true`.
2. **Данные получены.** Они кладутся в кэш по ключу `['account']`. Любой другой компонент с тем же ключом получит их сразу, без второго запроса.
3. **Свежесть.** Данные считаются свежими `staleTime` (у нас 10 секунд). Пока они свежие, повторный вызов `useQuery` не ходит на сервер.
4. **Фоновое обновление.** По истечении `refetchInterval` и при возврате на вкладку (`refetchOnWindowFocus`) запрос повторяется «тихо»: на экране остаются старые данные, пока не придут новые. Поэтому ничего не мигает.
5. **Ошибка.** Результат попадает в `query.error`, а предыдущие данные остаются в кэше. `retry: false` — повторять запрос автоматически не нужно: сервис либо отвечает, либо нет, а 401/409 повтором не лечатся.
6. **Один запрос на всех.** Если несколько компонентов запросили один ключ одновременно, на сервер уйдёт один запрос.

После изменения данных (отмена брони) достаточно вызвать `refetch()` или `queryClient.invalidateQueries({ queryKey: ['account'] })` — данные обновятся везде, где используется ключ.

### Где это у нас

- Клиент создаётся в `apps/web/app/plugins/vue-query.ts` (настройки по умолчанию в одном месте).
- Кабинет игрока: `apps/web/src/pages/account/model/useAccount.ts`. Публичный интерфейс не изменился (`bookings`, `sessions`, `authSessions`, `loading`, `error`, `load`), поэтому страница и карточки остались прежними. Ошибку можно задать снаружи (карточки сообщают о сбоях), поэтому `error` — записываемый `computed`.
- Запрос выполняется только на клиенте: личные данные не попадают в серверный рендеринг.

### Что не переведено

Админка использует Pinia-хранилище `useOperationsStore` с собственным `refresh()` и общим состоянием `pending`: оно координирует много связанных действий (пересадка, продление, оплата) и общий баннер результата. Переносить его на vue-query без реальной проблемы смысла нет. Бронирование на сайте (`useBookingSelection`) тоже осталось как есть: схема мест намеренно сбрасывается при смене времени.

## PWA

### Что такое PWA

PWA (Progressive Web App) — обычный сайт, который браузер умеет «установить»: иконка на домашнем экране, запуск без адресной строки, быстрый старт. Для этого нужны три вещи:

1. **Манифест** (`manifest.webmanifest`): название, иконки, цвета, стартовый адрес, режим `standalone`.
2. **Service worker** (`sw.js`): скрипт, который браузер запускает отдельно от страницы. Он видит все запросы сайта и может отдать ответ из своего кэша.
3. **HTTPS** (на `localhost` работает и без него).

### Как работает service worker у нас

Используется `workbox` (генерирует `sw.js` при сборке):

- **Предкэш.** При сборке составляется список файлов с хешами в именах (скрипты, стили, шрифты, иконки, WebP-картинки). Service worker скачивает их при установке и отдаёт мгновенно. Новая сборка меняет хеши, браузер обнаруживает новый `sw.js`, скачивает недостающее и переключается (`registerType: 'autoUpdate'`).
- **Страницы сайта** — стратегия `NetworkFirst`: сначала сеть (до 4 секунд), при отсутствии сети — последняя сохранённая версия. Поэтому открытая ранее страница откроется и без интернета.
- **Не кэшируется:** `/api/*`, админка, документация и Storybook. Данные клуба (брони, места) должны быть актуальными, устаревший ответ здесь вреднее, чем ошибка.
- В режиме разработки service worker отключён (`devOptions.enabled: false`), чтобы он не подсовывал старые файлы. Проверять PWA нужно на сборке (`pnpm build` и запуск в Docker-профиле `prod`).

## Проверка данных (Zod)

Zod описывает форму данных схемой и проверяет по ней значения во время работы программы. Он стоит в `@shift/contracts` (схемы ответов) и на сайте (формы).

**Ответы API.** В `packages/contracts/src/schemas.ts` лежат схемы `bookingSchema`, `gamingSessionSchema`, `availabilitySchema`, `catalogSchema` и другие. Рядом остаются обычные TypeScript-типы из `index.ts`; запись `satisfies z.ZodType<Booking>` заставляет компилятор следить, чтобы схема не разошлась с типом. Запрос с проверкой — `apiParsed(схема, путь)` из `shared/api`: если сервер вернул не то, что ждёт интерфейс (например, после изменения контракта), пользователь видит «Сервер вернул неожиданный ответ», а в консоль пишется, какое поле не совпало. Так проверяются данные кабинета (брони, сессии, устройства) и схема занятости мест на странице бронирования.

**Формы входа.** `features/authenticate/model/schemas.ts` содержит схемы входа, регистрации, восстановления и смены пароля. Тексты ошибок совпадают с серверными (`services/identity/lang/ru/validation.php`), поэтому пользователь видит одну и ту же формулировку независимо от того, кто заметил ошибку: браузер (мгновенно, без запроса) или сервер. Сервер проверяет всё повторно — клиентская проверка нужна только для удобства, защитой она не является. Если меняете правило на сервере (например, длину пароля), поменяйте и схему, а затем запустите `tests/unit/schemas.test.ts`.

## Заглушки загрузки (`UiSkeleton`)

Пока данные грузятся, показывайте `<UiSkeleton width="…" height="…" />` вместо подставного текста: так на экране не мелькает «Привет, игрок», а потом «Привет, Администратор», и макет не прыгает. Блок мерцает, скрыт от скринридеров; у контейнера ставьте `aria-busy`. Пример — заголовок и аватар в кабинете игрока.

## Иконки (`UiIcon`)

Все иконки живут в UI-ките и подключаются как компонент: `<UiIcon name="arrow-up-right" />`. Имена типизированы (`IconName`), поэтому опечатка видна при проверке типов. Размер по умолчанию равен размеру текста (`1em`), цвет берётся из `color` родителя (`currentColor`), толщина линии — свойство `stroke`. Декоративные иконки скрыты от скринридеров; если иконка несёт смысл, задайте `label`.

Набор — выборка из [Lucide](https://lucide.dev) (лицензия ISC). Он собирается скриптом, а не тянется целиком: чтобы добавить иконку, впишите её имя в список `NAMES` в `packages/ui/scripts/generate-icons.mjs` и выполните `pnpm --filter @shift/ui icons`. Файл `src/icons/data.ts` создаётся автоматически, руками его править не нужно. Каталог всех иконок виден в Storybook (раздел Icon).

## Даты (`date-fns`)

- Календарь UI-кита (`lib/date.ts`) считает «настенные» даты без часового пояса через `UTCDate` из `@date-fns/utc`: переход на летнее время не сдвигает дни. Сдвиг на месяц корректно «прижимается» к концу месяца (31 января + 1 месяц = 28 февраля).
- Время клуба (Москва) переводится в UTC и обратно через `TZDate` из `@date-fns/tz` (`shared/format`). Раньше для этого был ручной итеративный расчёт смещения.
- Текст («13 окт. 2026 г.», «июль 2026») по-прежнему формирует встроенный `Intl.DateTimeFormat('ru-RU')`: у него точнее русская локаль, чем у `date-fns`, а лишний вес не нужен.

## Токены оформления

Все цвета, размеры шрифта и радиусы заданы переменными в `packages/ui/src/tokens.css`; в стилях компонентов нет «голых» значений цвета и размера шрифта.

- **Цвета.** Базовые имеют смысловые названия (`--bg`, `--surface`, `--text`, `--muted`, `--acid`, `--danger`). Остальные оттенки названы по семейству и светлоте, % (`--olive-15`, `--gray-34`, `--red-72`). Полупрозрачные цвета: `--<цвет>-a<прозрачность>` (`--black-a55` = чёрный, 55 %).
- **Размер шрифта.** Шкала `--fs-9` … `--fs-96` (значение в px); адаптивные размеры заголовков — `--fs-fluid-<мин>-<макс>` (`clamp()` с px).
- **Единицы.** Размеры заданы в `px`. Исключение — `em` у логотипа и иконок: они должны масштабироваться вместе с окружающим текстом. Важно: при `px` размеры не следуют настройке размера шрифта в браузере.
- Если нужен новый цвет или размер, добавьте токен в `tokens.css`, а в компоненте используйте `var(--имя)`.

## Анимации появления (`v-reveal`)

Директива `v-reveal` (`apps/web/src/shared/ui/reveal.ts`) плавно показывает блок, когда он входит в экран: `v-reveal` — снизу вверх, `v-reveal.left/.right` — сбоку, `v-reveal.zoom` — с увеличением, `v-reveal="2"` — задержка по номеру в ряду (карточки появляются «лесенкой»). На сервере блок получает класс `reveal` (скрыт), в браузере `IntersectionObserver` добавляет `is-in` и запускает CSS-анимацию (`app/app.vue`). Свойства `translate`/`scale` отделены от `transform`, поэтому эффекты наведения не конфликтуют. Без JavaScript блоки показываются через `<noscript>`; при `prefers-reduced-motion` анимации сводятся к нулю. Дополнительно: шапка сайта закрепляется и размывает фон при прокрутке, сверху идёт полоска прогресса прокрутки, фон главного экрана медленно увеличивается и смещается параллаксом, стрелки в кнопках сдвигаются при наведении.

## Остальное

- **`@vueuse/core`.** Набор готовых composables. Используется `useScrollLock` (мобильное меню блокирует прокрутку страницы и снимает блокировку само) и `useIntervalFn` (пересчёт оставшегося времени).
- **`@formkit/auto-animate`.** Директива `v-auto-animate` на родителе списка добавляет плавную анимацию появления, удаления и перестановки дочерних элементов. Подключена к списку игровых сессий смены и таблице уведомлений. Учитывает `prefers-reduced-motion`.
- **Изображения.** Крупные иллюстрации (`club-hero`, `club-vip`) переведены в WebP: 1,8 МБ → 89 КБ и 2,0 МБ → 128 КБ. Исходные PNG остаются в репозитории. Отдельный модуль `@nuxt/image` не нужен: картинки статичны и заранее подготовлены, а галерея состоит из лёгких SVG.
- **Шрифты.** Они уже лежат в `public/fonts` и подключаются в `tokens.css`. Модуль `@nuxt/fonts` не нужен; вместо него в `<head>` добавлены `preload` для двух основных шрифтов, чтобы текст не «перескакивал» после загрузки.
- **SEO.** `robots.txt`, `sitemap.xml`, OpenGraph-теги и структурированные данные `EntertainmentBusiness` (адрес, телефон, часы, координаты) уже есть на главной странице; модуль SEO не требуется.
