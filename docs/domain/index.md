# Модель предметной области

Данные разделены по владельцам. У сервисов отдельные PostgreSQL базы; приложение не должно читать чужую базу напрямую.

| Сущность                    | Владелец      | Смысл                                                                                                                                                                                           |
| --------------------------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| User                        | Identity      | Аккаунт игрока или администратора; роль проверяется сервером.                                                                                                                                   |
| AuthSession / refresh token | Identity      | Авторизованная сессия входа и её отзыв. Это не игровая сессия.                                                                                                                                  |
| Zone                        | Club          | Зал или категория мест, например «Арена» и «VIP».                                                                                                                                               |
| Workstation                 | Club          | Компьютер, его зона, состояние, характеристики и позиция на схеме.                                                                                                                              |
| Tariff                      | Club          | Часовая цена для зоны.                                                                                                                                                                          |
| Booking                     | Booking       | Согласованное резервирование интервала одним пользователем.                                                                                                                                     |
| BookingItem                 | Booking       | Одно выбранное место с зафиксированной ценой и версией каталога.                                                                                                                                |
| GamingSession               | Booking       | Фактическое посещение, начатое администратором; может быть связано с бронью либо создано для гостя.                                                                                             |
| Notification                | Booking       | Запись в кабинете игрока и письмо: тип события, ключ дедупликации, статус отправки (`pending`, `sent`, `failed`, `skipped`), число попыток. Повтор доступен администратору только для `failed`. |
| AuditEntry                  | Booking, Club | Кто, когда и что изменил: брони, сессии, оплаты, повторы уведомлений, каталог и тарифы.                                                                                                         |
| ReportExport                | Booking       | Заказанная администратором CSV-выгрузка отчёта: период, статус (`pending`, `processing`, `ready`, `failed`, `expired`), срок хранения файла 24 часа.                                            |
| Outbox event                | Каждый сервис | Событие, записанное вместе с изменением доменных данных для дальнейшей публикации.                                                                                                              |

## Бронь и сессия

Бронь фиксирует обещанное место и временной интервал. Сессия отражает реальное использование компьютера. При создании брони Booking фиксирует стоимость и версию тарифа, поэтому последующие изменения цены не переписывают старую бронь. Бронь сама по себе не означает, что игрок пришёл или оплатил посещение.

Auth-сессия относится к входу в аккаунт. Игровая сессия относится к времени за компьютером. Они имеют разные владельцы, состояния и сроки.

## Состояния и конфликты

В подтверждённой модели сейчас встречаются статусы брони `confirmed`, `cancelled`, `checked_in`, `no_show`; игровые сессии имеют активное/ожидающее завершения и завершённое состояния. Переходы выполняются серверными операциями с проверкой роли и занятости. Бронь резервирует все выбранные места атомарно; конфликт одного места не должен оставлять частичную групповую бронь.

Время передаётся в API как timestamp, а представление должно согласовываться с часовым поясом клуба. Не полагайтесь на произвольный часовой пояс браузера: время клуба переводится в UTC и обратно по поясу клуба (`shared/format`).

## События

События содержат идентификатор, тип, версию схемы, время, correlation id и полезную нагрузку. Запись outbox делается в транзакции сервиса-владельца, затем publisher передаёт её RabbitMQ. Доставка может повторяться; обработчики должны дедуплицировать события. Состав событий и состояние очередей описываются по мере реализации в [руководстве API и событий](/developer/api).
